# BAMFORD DOORS WEBSITE REDEVELOPMENT
## Master Build Specification for Replit Agent

## 1. Project overview

Build a complete, professional, modern, responsive website for Bamford Doors, the trading name of F. Bamford (Engineering) Ltd.

Current website: https://bamforddoors.com/

The website must become a content-rich sales and education platform for organisations responsible for residential building security, communal entrances, public buildings and commercial properties.

The primary audiences are local authorities, housing associations, social housing providers, public sector organisations and education providers.

The website must help visitors understand the security problems they face, research suitable door products, understand the benefits of different materials and systems, explore real installations, access technical information and submit relevant enquiries.

This is a complete website redevelopment, not a landing page or visual prototype.

Before coding, audit the existing website, its navigation, individual pages, media, PDFs, downloads, case studies, news articles and current URLs. Create a migration inventory and use it to ensure that no important existing content is lost.

Use the supplied Bamford Doors Brand Book and Bamford Meeting Notes as the primary project documents.

Rewrite and reorganise content for clarity, usability, search visibility and lead generation while preserving verified facts, useful technical information and the meaning of existing content.

Do not invent company claims, technical specifications, certifications, awards, testimonials, customer relationships, guarantees or product performance figures.

## 2. Business objectives

The new website must:

1. Generate more qualified sales enquiries and project opportunities.
2. Educate existing and potential customers about security doors, product options, installation and long-term maintenance.
3. Establish Bamford Doors as an experienced and credible supplier of bespoke security doors and entrance systems.
4. Demonstrate the company's manufacturing capability, expertise, workforce and project experience.
5. Explain products and services in plain English, including technical concepts for visitors without specialist knowledge.
6. Support search visibility across Google and AI-powered discovery tools through accurate, structured, useful content.
7. Make it straightforward for authorised staff to maintain pages, products, case studies, news, images and downloadable documents.
8. Provide a foundation for ongoing content creation and website performance optimisation.

## 3. Brand and visual identity

Follow the supplied Bamford Doors Brand Book.

Primary brand colours:
- Bamford red: #C21B20.
- Black: #000000.
- White: #FFFFFF.
- Supporting neutral grey: establish a suitable accessible grey only after checking the original brand assets.

Typography:
- Montserrat Bold for primary headings.
- Montserrat Light for subheadings and body text, with a more readable weight where necessary.
- Use a locally hosted or reliably loaded web font where practical.

Logo:
- Use the supplied original Bamford Doors logo artwork.
- Preserve the original proportions, colours and clear space.
- Use the approved reversed white logo where required on dark backgrounds.
- Never redraw, distort, recolour, rotate or crop the logo.

Visual direction: balanced corporate.

The website should feel contemporary, established, reliable and technically competent. Use a predominantly white canvas, strong black typography, controlled red accents, high-quality photography and restrained dark sections.

Use architectural layouts, generous spacing, clear information hierarchy, consistent cards and simple red outline icons where they improve understanding.

Avoid excessive animations, generic stock imagery, oversized decorative gradients, unnecessary effects and template-like corporate design.

The website must look like Bamford Doors, not a generic construction company.

Use existing approved photography and video wherever suitable. Prioritise real doors, installations, the factory, manufacturing processes, staff and completed projects. Reuse existing media only when it is relevant, clear and of sufficient quality.

If new imagery is required, create an asset request list for the client. Do not represent stock photography or AI-generated imagery as actual Bamford products, staff, installations or facilities.

## 7. CMS and admin dashboard

Implement a secure content management system.

The chosen approach is content management, with authorised staff able to update website content without editing code. Keep the overall design system and page layouts controlled.

The CMS must support:

- Create, edit, preview and publish pages.
- Manage navigation and page hierarchy.
- Manage products, services and sectors.
- Create and edit case studies.
- Manage news articles, authors, categories and tags.
- Schedule article publication.
- Upload, organise and replace images.
- Add image alt text and captions.
- Upload, replace and categorise technical PDFs and other downloads.
- Edit page titles, meta descriptions, canonical URLs and social sharing metadata.
- Manage FAQ entries.
- Manage testimonials and their approval status.
- Review form submissions.
- View publication status and update dates.

Use reusable page templates and structured content types rather than hard-coded content repeated across pages.

Implement authentication and role-based access. At minimum, provide an administrator role and an editor role. Editors should be able to manage content without accessing sensitive system settings.

Protect admin routes and all write operations on the server. Validate input, use secure sessions and store secrets in environment variables.

Provide preview functionality before publishing.

Do not expose admin functionality, database credentials or API keys to unauthorised users.

## 8. Enquiry and lead generation functionality

Build functional forms for:

1. General enquiries.
2. Product enquiries.
3. Maintenance enquiries.
4. Stock condition survey requests.
5. Callback requests.

Forms should request only the information necessary to process the enquiry. Use clear labels, accessible validation, useful success and error messages, server-side validation and spam protection.

Product enquiries should allow the visitor to identify the product of interest. Relevant forms should capture organisation, contact details, enquiry type and a message.

Where appropriate, include optional project location, approximate project size, timescale and attachment fields. Do not make every field compulsory.

On successful submission:
- Save the enquiry securely.
- Record the submission date and form type.
- Send an email notification to a configurable recipient.
- Display a confirmation message to the user.
- Prevent duplicate submissions where practical.
- Provide a way for authorised staff to review and manage submissions.

Email delivery must use a configured provider or SMTP integration. Do not simulate email delivery in production.

Do not invent the notification email address. Make it configurable through the admin settings or environment variables.

Add clear CTAs throughout the site:
- Request a Consultation.
- Request a Stock Condition Survey.
- Enquire About This Product.
- Request a Callback.
- Download the Door Selector Guide, once an approved guide exists.
- Book a Site Survey, where this reflects the actual process.

The proposed free security audit or tenant safety assessment must not be advertised as an established service until Bamford confirms the offer, scope and terms.

For gated downloads, make the form and consent requirements configurable. Do not require marketing consent as a condition of receiving a requested document unless legally justified.

## 18. Replit Agent implementation workflow

Work in the following phases.

Phase 1: Audit
- Inspect the current website and supplied project documents.
- Inventory all pages, products, services, news, case studies, media and downloads.
- Identify missing information and factual claims requiring approval.
- Produce the proposed sitemap and URL migration plan.

Phase 2: Design system and prototypes
- Implement the brand colours, fonts, logo handling, buttons, spacing, navigation and reusable components.
- Build the homepage and representative product, service, sector and case study page templates.
- Check the visual design before generating the full site.

Phase 3: Website and content
- Build all approved pages and navigation.
- Migrate and improve existing content.
- Create reusable content structures and related-content links.
- Add verified imagery and technical downloads.

Phase 4: CMS and enquiries
- Implement authentication, content management, publication scheduling and media management.
- Build all enquiry forms, secure submission storage and configured email notifications.

Phase 5: SEO and integrations
- Implement redirects, metadata, schema, sitemap, robots.txt and analytics integration.
- Test the keyword and page mapping.

Phase 6: Quality assurance
- Test functionality, responsiveness, accessibility, security, SEO and performance.
- Resolve defects and produce a migration and verification report.

Phase 7: Launch preparation
- Prepare deployment documentation and the client handover.
- Keep production changes under explicit human approval.

At the end of each phase, report what has been completed, what remains, any blockers and any client decisions required.

Do not attempt to generate the entire website as one unreviewed block of code. Build and test it incrementally.

## Final instruction

The finished product must be a complete, professional, working Bamford Doors website that the company can maintain and develop over time.

Prioritise factual accuracy, ease of use, strong product education, lead generation, a consistent brand identity and long-term search visibility.

When information is missing, create a clearly labelled task for the client instead of inventing the answer. Never treat a visual placeholder as completed functionality.

Start by auditing the existing website and producing the migration inventory, proposed sitemap, content model and list of outstanding decisions before implementing the site.
